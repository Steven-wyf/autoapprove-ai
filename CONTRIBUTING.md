# Contributing

## Ground Rules

- Keep the first prototype narrow: evidence-gated SaaS approval.
- Prefer small, reviewable pull requests.
- Do not commit secrets, API keys, SOC 2 PDFs, vendor confidential reports, or customer data.
- Do not commit `AGENTS.md`; it is intentionally ignored.
- Add new demo assumptions to `docs/`.

## Suggested Workstreams

- Agent workflow and state model.
- TrueFoundry AI Gateway integration.
- MCP tool wrappers.
- Guardrail policy checks.
- Demo fixtures and failure injection.
- UI or CLI demo surface.

## Commit Style

Use concise conventional commits when possible:

- `docs: add approval policy rubric`
- `feat: add evidence collection workflow`
- `test: add guardrail fixtures`
